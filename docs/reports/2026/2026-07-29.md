## 三、当日技术观察

### 值得关注的变化
- PR #31120 实现了 JEP 401（Value Objects 预览版）的首个预览版本，涉及 C2、C1 编译器及 GC 模块，支持 RISC-V、AArch64 和 x86 架构，标志着值对象特性的关键进展。[详情](https://github.com/openjdk/jdk/pull/31120)
- PR #32080 针对 RISC-V 后端优化了 CRC32 和 CRC32C 的切片处理（slicing-by-8），提升标量路径的性能，涉及 C2 编译器模块。[详情](https://github.com/openjdk/jdk/pull/32080)
- PR #32079 优化了 RISC-V C2 后端中 RVV vset 指令的生成，减少了多余指令的发射，提升向量指令效率。[详情](https://github.com/openjdk/jdk/pull/32079)
- PR #32077 利用 RISC-V Zfa 扩展的 `fround.d` 指令实现 C2 的双重舍入操作，改进浮点数舍入的硬件支持。[详情](https://github.com/openjdk/jdk/pull/32077)
- PR #32076 修正了 RISC-V 向量更新 CRC32 时错误假设尾部元素未被破坏的问题，解决了 QEMU 上测试的间歇性失败。[详情](https://github.com/openjdk/jdk/pull/32076)
- PR #32074 改进了 NMT（Native Memory Tracking）对 malloc 峰值统计的准确性，纳入了 malloc 头部开销，提升诊断数据的精确度。[详情](https://github.com/openjdk/jdk/pull/32074)
- PR #32078 修复了 HTTP/2 连接在接收 GOAWAY 帧且无活动流时未关闭的问题，增强网络模块的协议兼容性和稳定性。[详情](https://github.com/openjdk/jdk/pull/32078)
- PR #32086 修复了 `Class::desiredAssertionStatus` 在接收原始类型或数组类时的断言状态错误，完善核心类库的断言机制。[详情](https://github.com/openjdk/jdk/pull/32086)

### RISC-V 观察
- 多个 PR 聚焦于 RISC-V 架构的编译器后端优化，包括 CRC32/CRC32C 算法的切片优化（#32080）、RVV 向量指令的 vset 指令生成优化（#32079）、利用 Zfa 扩展指令实现双重舍入（#32077）以及修复向量更新 CRC32 的错误假设导致的测试失败（#32076）。
- 这些改进表明 RISC-V 架构的热点编译器支持和指令生成正持续完善，提升了性能和稳定性。
- PR #29499 关于移除冗余 vset 指令的尝试已关闭，显示相关优化仍在调整中。

### 风险与回归
- PR #32076 修复了 RISC-V 向量 CRC32 相关的错误，之前导致测试在 QEMU 上间歇性失败，需关注修复后在多种环境的稳定性验证。
- PR #32074 对 NMT 统计方式的调整可能影响诊断数据的历史对比，需验证新旧统计数据的兼容性和准确性。
- PR #32078 修复 HTTP/2 连接关闭问题，需关注网络模块在边界条件下的行为，防止引入新的连接管理问题。
- 证据不足，无法判断其他 PR 是否存在潜在风险或回归。
